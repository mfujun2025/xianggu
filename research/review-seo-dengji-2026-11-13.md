## 4. 结构化数据建议

### 4.1 Article / FAQPage 双 JSON-LD 能否被正确解析：可以，但 FAQ 文本被污染

模板（engine.py:202–203）输出**两个独立** `<script type="application/ld+json">`，互不嵌套，搜索引擎可分别解析 ✓。

| 检查项 | 状态 | 说明 |
|---|---|---|
| `Article` 字段 | ✓ | `@context/@type/headline/description/datePublished/dateModified/inLanguage/mainEntityOfPage/author(Organization)/publisher(Organization)/wordCount` 齐备 |
| `FAQPage` 字段 | ✓ | `mainEntity[6].Question.name + acceptedAnswer.Answer.text`，6 组与页面可见 FAQ 一一对应 |
| 纯文本清洗 | ✓ 设计意图 | `build_opp.py:63-69` 的 `rt_text()` 把 `[[slug\|锚文本]]` 退化为锚文本、`[text](url)` 退化为 `text（url）`、`**` 去星号，避免标记污染 schema |
| 域名一致性 | ✓ | `canonical`（:201）、`og:url`（:196）、`Article.mainEntityOfPage`（engine.py:109）均用同一 punycode 常量 `xn--hp1av06b.xn--fiqs8s`；`og:title`/`og:description` 与 `<title>`/meta desc 同源 |
| **FAQ 答案 HTML 实体污染** | **✗ 需修** | 见下 |

**问题（实测）**：`rt_text()` 第一行 `s = engine.esc(s)` → `html.escape(quote=False)` 会把 FAQ 答案中的 `<` / `>` 转成 `&lt;` / `&gt;`。Q1 答案含 `>0.8cm`、`<6 分`、`<2.0%` 等数值，实测 **7 处污染**，写入 JSON-LD 后为：

```
"text": "…以干厚菇为例…：特级菌盖厚 &gt;0.8cm、开伞度 &lt;6 分、菌褶淡黄色…"
```

JSON-LD **语法仍合法**（不会报错、不影响收录），但搜索引擎读到的答案文本带 HTML 实体，FAQ 富媒体摘要 / 语音答案可能把 `<6 分` 呈现成 `&lt;6 分`，损害最关键的数值信息。

**精确修复位置**：`drafts/build_opp.py` 第 63–69 行 `rt_text()`，删除 `s = engine.esc(s)` 一行即可。`build_faq_schema()` 内部用 `json.dumps(..., ensure_ascii=False)`，会自行完成 JSON 层面的转义；`html.escape` 只应服务于 HTML 输出，不应进入 JSON-LD 文本。删掉后 LINK_RE / EXT_RE / BOLD_RE 替换逻辑不受影响（去标记不依赖 HTML 转义）。若担心 `</script>` 注入，可在去标记后仅做一次 `.replace('</', '<\\/')` 保护——本稿 FAQ 答案不含该串，直接删最安全。（`Article` schema 的 headline/description 取自原始未转义的 `a`，不受此问题影响 ✓）
